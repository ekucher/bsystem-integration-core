# P0.3 — Service Identities & Adapter Framework

## Goal

Add a machine-to-machine security boundary and a stable adapter contract before integrating external business systems.

## Human vs service access

Human requests and service requests are intentionally separated.

```text
Human user
  -> /api/v1/*
  -> authentik token
  -> human RBAC
  -> USR-*

Service identity
  -> /api/service/v1/*
  -> authentik token
  -> BSYSTEM-Services membership
  -> service permissions
  -> SVC-*
```

A service token must never be treated as a human user token.

## Service identity persistence

The first accepted service request allocates a stable Global ID:

```text
authentik subject -> SVC-000001
```

Persisted attributes:

- authentik subject;
- stable `SVC-*` ID;
- display name;
- username;
- groups;
- enabled state;
- created/last-seen timestamps.

Access tokens and client secrets are never persisted.

## Base service group

All machine identities must be members of:

```text
BSYSTEM-Services
```

P0.3 grants the base service permission set:

```text
adapters.read
events.publish
global_ids.read
```

Later milestones will replace this fixed set with persistent service roles/scopes.

## Service API

```text
GET /api/service/v1/whoami
GET /api/service/v1/adapters
GET /api/service/v1/adapters/health
```

All endpoints require a bearer token accepted by authentik and membership in `BSYSTEM-Services`.

## Adapter contract

Every adapter implements:

```go
Info() Info
Health(context.Context) Health
```

`Info` includes:

- stable adapter ID;
- name;
- adapter version;
- runtime status;
- capabilities.

Initial planned adapters:

```text
espocrm
redmine
outline
```

They are registered as `disabled` until configuration and real clients are implemented.

## Adapter principles

1. Domain systems remain source of truth.
2. Integration Core never performs direct cross-product SQL.
3. Adapter errors must not crash unrelated adapters.
4. Each adapter exposes explicit capabilities.
5. Health is adapter-specific and queryable.
6. Credentials are injected through environment/secrets, never committed.
7. Adapter writes require explicit capability and authorization checks.
8. External IDs are mapped to BSYSTEM Global IDs.

## Persistence added

```text
service_identities
adapter_registry
```

The runtime adapter registry is currently code-backed. `adapter_registry` is reserved for persistent enablement/configuration metadata in the next increment.

## Events

New platform event:

```text
service_identity.created
```

Envelope standardization is part of the next P0.3 increment.
